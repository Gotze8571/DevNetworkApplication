# Database

PostgreSQL 16, run through `docker-compose.yml` at the repo root.

## Connection (local defaults)

| Setting | Value |
|---|---|
| Host | `localhost:5432` |
| Database | `devnetwork` |
| User / password | `devnetwork` / `devnetwork` |

Override these with `POSTGRES_DB`, `POSTGRES_USER` and `POSTGRES_PASSWORD` in a root `.env` file.

Start only the database:

```bash
docker compose up database
```

## Schema migrations

The schema is owned by the backend and managed with **Flyway**. Migrations live in
[`backend/src/main/resources/db/migration`](../backend/src/main/resources/db/migration) and run automatically when the backend starts.

- Name new files `V<next number>__<description>.sql`, e.g. `V2__create_connections_table.sql`.
- Never edit a migration that has already been applied; add a new one instead.
- Hibernate is set to `validate`, so the app refuses to start if entities and schema disagree.

## Tables

| Table | Purpose |
|---|---|
| `users` | Accounts (email, display name, BCrypt password hash) |
| `profiles` | One per user: headline, bio, location, links |
| `skills` / `user_skills` | Shared skill tags and which users have them |
| `experiences` | Work history per user |
| `educations` | Education history per user |
| `connections` | Connection requests between users (`PENDING` or `ACCEPTED`; declined or removed ones are deleted). One per pair |
| `posts` | Feed posts |
| `post_comments` / `post_likes` | Comments and likes on posts |

Only `users`, `profiles` and `connections` are used by the app so far; the other tables are ready for future features.

All ids are UUIDs generated by the application. Deleting a user cascades to everything they own.

## Reset local data

```bash
docker compose down -v   # removes the db-data volume
```
